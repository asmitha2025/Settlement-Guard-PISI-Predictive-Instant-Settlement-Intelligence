PISI Methodology & System Architecture

A complete reference for PISI's autonomous agent architecture, 47-feature ML pipeline, 3-tier risk governance, bounded stopping rules, cryptographic audit trails, and self-improving active learning loop.

🔄 1. The Autonomous Agent Loop Continuous Cycle · <10ms

PISI functions as a continuous autonomous agent operating across five deterministic phases: Perceive, Reason, Decide, Act, and Learn. Unlike reactive rule-based alerting systems, PISI bridges funds before degraded banking rails disrupt merchant operations.

STEP 1 · PERCEIVE
Webhooks & Feeds
Ingests 6 Razorpay event streams, real-time payment capture deltas, failure error codes, and bank latency telemetries.
→
STEP 2 · REASON
XGBoost & Vitality
Computes 47 continuous features, evaluates 5-dimensional Bank Vitality Index, and generates calibrated failure probability.
→
STEP 3 · DECIDE
3-Tier Gating
Validates confidence floor (0.70) against safety gates, merchant opt-outs, and liquidity caps to issue ACTIVATE, ESCALATE, or MONITOR.
→
STEP 4 · ACT
API Execution
Calls Razorpay Instant Settlement Bridge API for T+0 merchant payouts, creates SHA-256 audit entry, and notifies merchant.
→
STEP 5 · LEARN
Retrain Loop
Tracks drift via Population Stability Index (PSI), ingests closed reconciliation batches, and triggers zero-downtime hot reloading.
🧠 2. The ML Pipeline (How the Model Works) 47 Features · XGBoost + CalibratedClassifierCV
Raw Telemetry → 47-Feature Extraction → XGBoost Classifier → Isotonic Calibration → Threshold Gate → Autonomous Action
47 Continuous Features
5D Bank Vitality composite: Error Vitality (EV), Temporal Health (TH), Settlement Velocity (SV), Network Resilience (NR), and Predictive Markers (PM). Augmented by 24 rolling error window frequencies and 18 payment volume acceleration vectors.
Calibrated Model Architecture
Gradient Boosted Trees (XGBoost) wrapped with CalibratedClassifierCV (Isotonic regression). Raw tree margins are calibrated into true empirical probabilities, ensuring confidence scores represent actionable real-world risk.
Temporal Cross-Validation
Time-sliced forward-chaining validation strictly prevents look-ahead leakage. Rigorously tested against 1,000 synthetic banking outage permutations achieving 100% precision on true settlement failures.

🛡️ 4. The Stopping Rules & Safety Gates Risk-Gated Liquidity Controls

To protect Razorpay's balance sheet against runaway execution or catastrophic cascading defaults, four immutable circuit breakers are hardcoded into the execution layer:

🔒
30% Capital Pool Cap
Maximum of ₹1.50 Cr deployed simultaneously from the ₹5.00 Cr instant settlement pool to prevent systemic liquidity depletion.
⚡
10 Concurrent Bridges
Hard concurrency throttle limiting simultaneous open settlement bridges per banking institution to prevent runaway API storms.
💰
₹50,000 Max Ticket
Per-transaction advance limit preventing single anomalous enterprise payments from exhausting the corridor's liquidity allocation.
⚙️
Merchant Treasury Flags
Zero-override adherence to merchant-defined opt-out directives, fee sensitivity thresholds, and custom risk-tolerance policies.

🔁 6. The Learning Loop (Continuous Self-Improvement) Statistical Drift Detection

Banking error patterns evolve as core banking software is updated. PISI continuously benchmarks real settlement outcomes against its predictions to adapt autonomously without human engineering intervention.

1. Deploy Model → 2. Monitor Batches → 3. Detect Drift (PSI > 0.20) → 4. Offline Retraining → 5. Validation Gate (≥95%) → 6. Hot Reload

When the Population Stability Index (PSI) flags statistical distribution shifts, an asynchronous training pipeline fits new trees on the latest rolling 30-day reconciliation dataset. The candidate model is evaluated against historical adversarial failure logs. Only if precision remains above 95% and false positives remain zero does the model promote to live inference.
